# Tech Terminal - PRD

## 概要

プログラミングスクールのメンター向けに、Qiita・Zenn・ブログなどの技術記事をまとめて管理できる Web アプリケーション。

### 背景・課題

- 有用な技術記事が Slack、スプレッドシートなど複数箇所に散在
- 時間が経つと忘れ去られ、技術ノウハウが蓄積されない
- 同じ記事を何度も探す非効率が発生

### ゴール

- 記事を一元管理し、メンター間でナレッジを共有・蓄積できる状態を作る

---

## ターゲットユーザー

- プログラミングスクールのメンター（スタッフ）

---

## MVP 機能

| 機能                     | 説明                                                 |
| ------------------------ | ---------------------------------------------------- |
| **URL ブックマーク登録** | URL を貼って記事を追加（タイトル自動取得は将来対応） |
| **言語/コース分類**      | Python, Web, GameApp などで分類                      |
| **タグ付け**             | 自由にタグを付与できる                               |
| **一覧表示**             | 言語/コース、タグでフィルタリング可能                |
| **検索**                 | タイトル・タグで検索                                 |
| **投稿者記録**           | 誰が追加したかを記録（名前入力）                     |
| **メモ欄**               | 記事に対するコメント・補足を記載                     |

---

## 技術構成

| 項目           | 選定                 |
| -------------- | -------------------- |
| フロントエンド | Next.js (App Router) |
| バックエンド   | Next.js API Routes   |
| データベース   | Firebase (Firestore) |
| デプロイ       | Vercel               |
| 認証           | なし（MVP）          |

### 選定理由

- **Next.js API Routes**: MVP の規模（CRUD 4 エンドポイント程度）では分離不要
- **Firebase**: スケーラブル、将来 Firebase Auth 追加も容易
- **Vercel**: 無料枠十分、Firebase との相性も ◎
- **認証なし**: 個人情報を扱わない内部ツールのため MVP では省略
